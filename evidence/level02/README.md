# レベル2 の構築記録

状態: **未実施（NOT RUN）**。このページは実行前の案内です。

最初のAWS実測は、[既存のEC2 Webサーバーキット](../../projects/02-ec2-web-server/handson/README.md)1件で行います。構成は VPC → パブリックサブネット → EC2 1台／Apache です。ALB・RDS・NATゲートウェイは追加しません。

1. **準備（10〜15分、作成はまだ行わない）**: キットと[コスト管理](../../docs/03-cost-management.md)を読み、実行アカウント、リージョン、予算、終了時刻を決めます。SSHの許可元、HTTPの公開範囲、削除対象を説明できるか確認します。予算通知は支出の強制停止ではありません。
2. **構築**: 実AWS操作と費用負担を決めた後、キットの手順で `build.sh` を実行します。開始・終了時刻、終了コード、失敗箇所を記録します。成功表示だけではWebサーバーの正常性は判断しません。
3. **疎通と観測**: 下表で正常性を確認します。期待値と実測値は別欄に残します。監視はこの短時間の観測範囲に限り、24時間運用やアラーム通知済みとは書きません。
4. **削除・費用確認**: `cleanup.sh` は失敗・未確認の操作を表示して非0で終了し、状態ファイルとローカル秘密鍵を保持します。原因を解消して再実行し、作成対象の EC2・EBS・Elastic IP・SG・ルートテーブル・IGW・サブネット・VPC・キーペアを確認します。残存があれば失敗として追跡し、翌日以降に請求を別途確認します。状態ファイルは手元の非公開領域だけで扱います。

| 確認 | 期待する結果 | 記録する証跡 |
|---|---|---|
| EC2 のステータスチェック | 対象インスタンスが正常 | 時刻・確認画面・対象の対応関係 |
| `curl -sS -o /dev/null -w '%{http_code}\n' http://<Elastic IP>/` | HTTP `200`、curlの終了コード `0` | HTTPステータスと終了コードを別々に記録 |
| SSH先で `systemctl is-active httpd` | `active` | 実行時刻と出力 |
| SSH先で `systemctl is-enabled httpd` | `enabled` | 実行時刻と出力。再起動試験済みとは区別 |
| EC2 の CloudWatch メトリクスで `CPUUtilization` と `StatusCheckFailed` を確認 | 取得値・期間を読める。ステータスチェック失敗は `0` | 観測開始・終了、期間、実測値。データ未到着は `UNKNOWN` |
| 各サービスで削除対象を照合 | 対象EC2は `terminated`、関連リソースは残っていない | リソース別の確認時刻と結果。別用途の既存リソースは対象外 |

記録は [handson-record.md](../templates/handson-record.md) をコピーし、このディレクトリに `YYYY-MM-DD.md` として保存します。HTTPは疎通学習用で、秘密情報やログイン画面を載せません。IP・アカウントID・鍵・状態ファイルは公開しません。

最後に自分の言葉で「なぜSSHを自分のIPに限定したか」「HTTP 200だけでは何が分からないか」「削除スクリプトの終了だけで片付け完了と言えない理由」を各1〜2文書きます。分からない項目は次の確認事項として残します。
