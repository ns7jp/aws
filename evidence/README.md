# 構築証跡(エビデンス)

このディレクトリは、各案件のハンズオンキットを**実際のAWSアカウントで実行した記録**を残す場所です。

ドキュメントやスクリプトが存在するだけでは「実際に構築できた」証明にはなりません。面接では「本当に手を動かしたのか」「トラブルにどう対処したのか」を見られるため、実行ログ・スクリーンショット・所要時間・費用を証跡として残しておくと、説得力が大きく上がります。

> 🧠 **覚え方のコツ**: 証跡は「実験ノート」です。理科の実験と同じで、「何をして(手順)」「何が起きて(結果)」「どう考えたか(考察)」の3点セットで残すと、あとから自分でも他人でも再現・評価できます。

## 記録の残し方

1. `templates/handson-record.md` をコピーして `levelXX/YYYY-MM-DD.md` として保存します(例: `level01/2026-09-10.md`)
2. 構築前に **予算アラート**を設定し、開始時刻をメモします
3. `build.sh` / `terraform apply` の出力から、**秘密情報(アカウントID・パスワード・アクセスキー・IPアドレス)を伏せた上で**要点を貼り付けます
4. 動作確認のスクリーンショットを `levelXX/images/` に保存し、Markdown から参照します
5. `cleanup.sh` / `terraform destroy` の実行後、**請求画面で残存リソースがないこと**を確認して記録します

## 証跡に含めてはいけないもの

| 含めてはいけない情報 | 理由 | 代わりに書くこと |
|---|---|---|
| AWSアカウントID、アクセスキー、パスワード | 悪用されるリスク | `XXXXXXXXXXXX` のように伏せ字にする |
| Elastic IP・ALBのDNS名などの実アドレス | 削除後も推測の手がかりになる | `xx.xx.xx.xx` / `<ALB DNS>` と書く |
| `.pem` ファイル、`.handson-state.env`、`tfstate` | 秘密鍵・リソースIDを含む | 内容は貼らず「生成した」と書く |
